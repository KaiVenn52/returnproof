Trace the main action

  1. src/app.mjs — the source-form submit handler passes receipt and policy into analyze, then displays the exact evidence lines.
  2. src/domain.mjs — analyze suggests supported fields. compareWindows exposes competing dates without choosing a rule; source actions select the original line and review shortcuts remain unconfirmed. deadline adds calendar days, subtracting one only when the anchor is day one. confirmCase binds the current interpretation to current sources.
  3. src/exports.mjs — calendar calls isConfirmed again before making an all-day event. UI button state is not the only protection.
Why November 9 can become November 8

October 10 + 30 days gives November 9 when October 11 is day one. Counting October 10 as day one subtracts one day, giving November 8. See the test named anchor-inclusive and anchor-exclusive windows differ by exactly one day in tests/domain.test.mjs.

Reusable practice: write down the counting assumption before implementing the date calculation, then test both interpretations with the same input.

Where a future change belongs

Supported wording: analyze. Calendar math: deadline/addDays. Confirmation invalidation: input handlers and signature. Persistence and deletion: saveCase, bind and loadCases. Drafts stay uncalculated; source edits saved after checking reopen as drafts until another check. Export format: exports.mjs. Layout: styles.css.

Try both counting conventions in the running app and compare the result with the test. This is a suggested learning activity, not a recorded learner completion. Public source, video hosting and final submission are separate remaining gates.
